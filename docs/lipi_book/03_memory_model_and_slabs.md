# অধ্যায় ৩: মেমরি মডেল, স্ল্যাব ও অ্যারেনা অ্যালোকোটর (Memory Model, Slabs & Arenas)

> **"মেমরি লিক বা মেমরি ফ্র্যাগমেন্টেশন কোনো অনিবার্য ভাগ্য নয়; সঠিক আর্কিটেকচারই পরম মুক্তি।"**

---

## ৩.১ সার্বভৌম মেমরি দর্শন (The Sovereign Memory Philosophy)
লিপিতে কোনো ভারী গার্বেজ কালেক্টর বা জটিল রেফারেন্স কাউন্টিংয়ের ওভারহেড নেই। এর মেমরি আর্কিটেকচার তিনটি স্তম্ভের ওপর প্রতিষ্ঠিত:
1. **সরাসরি লিনাক্স mmap/brk কার্নেল ইন্টারফেস**: রানটাইমে মেমরি বরাদ্দের জন্য কোনো সি লাইব্রেরির `malloc()` কল হয় না; সরাসরি `sys_mmap` (syscall 9) এবং `sys_munmap` (syscall 11) ব্যবহৃত হয়।
2. **অ্যারেনা অ্যালোকোটর (Arena Allocator)**: ব্যাচ প্রসেসিং এবং লাইফটাইম-বাউন্ড টাস্কের জন্য একক মেমরি চাঙ্ক থেকে দ্রুততম ও(১) অফসেট বরাদ্দ এবং টাস্ক শেষে একযোগে মুক্তকরণ।
3. **স্ল্যাব অ্যালোকোটর (Slab Allocator)**: নির্দিষ্ট আকারের অবজেক্টগুলোর (যেমন ফাইবার কনটেক্সট, ডাটাবেজ নোড, নেটওয়ার্ক ফ্রেম) জন্য ক্যাশ-বান্ধব স্ল্যাব পুলিং, যা ইন্টারনাল ও এক্সটারনাল ফ্র্যাগমেন্টেশন সম্পূর্ণ নির্মূল করে।

```
    Kernel Space (Ring 0)
    ─────────────────────────────────────────────────────────────────
         ▲ sys_mmap (syscall 9)               ▲ sys_munmap (syscall 11)
    ─────┼────────────────────────────────────┼───────────────────────
    User Space (Ring 3) - Pure Lipi Engine
         │
    ┌────┴──────────────────────────────┐
    │     4KB / 2MB HugePage Virtual    │
    └────┬──────────────────────────────┘
         ▼
    ┌──────────────────┬──────────────────┬──────────────────┐
    │  Slab 32 Bytes   │  Slab 64 Bytes   │  Arena Allocator │
    │  (Fast Node Pool)│  (Fiber State)   │  (Batch Request) │
    └──────────────────┴──────────────────┴──────────────────┘
```

## ৩.২ র মেমরি রিড ও রাইট ইন্ট্রিনসিক্স (Raw Memory Intrinsics)
হার্ডওয়্যার ও অপারেটিং সিস্টেম প্রোগ্রামিংয়ের জন্য লিপি সরাসরি বাইট-লেভেল মেমরি এক্সেস প্রদান করে:

```lipi
include "universe/core/memory.lp"

fn main
    // ৮ বাইট (৬৪-বিট) মেমরি বরাদ্দ করা
    বাফার = sys_alloc(64)

    // অফসেট ০-তে ৬৪-বিট পূর্ণসংখ্যা লেখা
    sys_poke(বাফার, 42)

    // অফসেট ৮-তে বাইট লেভেলে কাজ করা
    sys_poke8(বাফার + 8, 255)

    // মেমরি থেকে মান পড়া
    মান = sys_peek(বাফার)
    বাইট_মান = sys_peek8(বাফার + 8)

    say "সংরক্ষিত মান: " + to_str(মান)
    say "সংরক্ষিত বাইট: " + to_str(বাইট_মান)
    return 0

main()
```

## ৩.৩ অ্যারেনা অ্যালোকোটরের বাস্তব ব্যবহার (Arena Pattern)
অ্যারেনা ব্যবহারের মাধ্যমে প্রতি রিকোয়েস্টে আলাদা আলাদা ফ্র্যাগমেন্টেড মেমরি কলের পরিবর্তে একবারে মেমরি নিয়ে কাজ করা যায়:

```lipi
include "universe/core/arena.lp"

fn process_batch_data count
    // ১ মেগাবাইট আকারের সার্বভৌম অ্যারেনা তৈরি
    arena = arena_new(1048576)

    i = 0
    while i < count
        // অ্যারেনা থেকে O(1) স্পিডে মেমরি অফসেট বরাদ্দ
        block = arena_alloc(arena, 64)
        sys_poke(block, i * 100)
        i = i + 1

    say "ব্যাচ প্রসেসিং সফল: মোট নোড " + to_str(count)

    // সম্পূর্ণ অ্যারেনা তাৎক্ষণিক মুক্ত (Zero Deallocation Overhead)
    arena_free(arena)
    return 0
```
